## 實際操作

- 點角色身體後，瀏覽器焦點落在輸入框。桌面小窗開着時，可收起和重開待辦詳情。窄屏在 390 × 520 的短視窗也可觸及送出按鈕。
- 在已選待辦問「這個要帶哪些東西？」。從小窗開啟完整對話後，讀到同一題和同一答案。點助手頁的角色會揮手。
- 從原回答發起討論，展開三個具名觀點、暖黃小結及來源，點來源卡可打開再關閉。畫面沒有多一個「討論這個回答。」氣泡，接着送出的普通問題沒有討論標記。
- 把下一題的回覆設為服務失敗，畫面只出現一次原因。點該行的「開始新訊息」可輸入下一題。桌面另點停止，控制器向同一則訊息發出取消請求。
- 兩個尺寸均操作過共用附件選單、相簿和拍照入口，以及語音介面的開啟與取消。未授予實體咪高峰或相機權限。

## 證據邊界

待辦、身份、訊息保存及頁面選取使用本機 Firebase 模擬器及合成家庭。另於桌面和窄屏各以正式 Firestore Agent 接口、可控模型供應端及獨立審核流程完成一次原待辦讀取，核對已保存的提問綁定該孩子和待辦版本，回覆「帶放大鏡和畫紙。」。

動圖採同一正式前端。在隔離瀏覽器內重播固定的聊天回答、討論、失敗和取消狀態，合成三方討論來自通過既有討論測試及完整 API 格式核對的結果。三方文字和參考卡都是測試資料。初次全鏈測試中，普通審核回應多了一個欄位，其後修正測試供應端，兩個尺寸均成功讀答。首輪桌面討論超過瀏覽器等候時間，核查時原操作仍在處理。窄屏討論因三段合成發言沒有相應引用，審核拒收，其後該本機帳戶顯示當日用量上限。另一個本機測試組合在普通提問回傳服務不可用。這些嘗試均保留為未通過。

前端 TypeScript 檢查及六項定向測試通過，涵蓋原回答與討論的關聯、分頁、普通手打同字句，以及原有討論順序和審核契約。正式模型的帳戶額度、iPhone／Android 實體鍵盤與錄音上傳仍待相應環境驗收。
