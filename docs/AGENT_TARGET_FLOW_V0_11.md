# 育伴港｜v0.11 需求完成後的 Agent 目標流程圖

- 用途：讓使用者核對「按 v0.11 做完後，是否符合心意」，不是現有程式或部署流程圖。
- 需求基準：[REQUIREMENTS_BACKLOG.md v0.11.0](https://github.com/2NTTY/child-ai-caregiver/blob/40e6d15ed13b5aeb49da2af92711c2884b9b0460/docs/REQUIREMENTS_BACKLOG.md)，文件日期 2026-10-29（香港時間），PR #381 原需求提交 `40e6d15ed13b5aeb49da2af92711c2884b9b0460`。
- 本文是原需求的圖解，不新增需求、固定技術方案或執行授權；已確認方向、工程建議及待定項仍以原需求文件為準，也不取代 SPEC／PLAN／STATUS。
- 圖中箭嘴表示資料／結果流向；「按需」不是每題必跑。分支位置不指定並行方式、固定模型回合數或每次相同次序。

**核心：一個主聊天工具循環；需要時才找專責協助。三角色討論由使用者另行選擇，背景維護則獨立運作。**

## 1. 兩個獨立選擇：聊天模式 × 是否討論

依據：[REQ-003](REQUIREMENTS_BACKLOG.md#req-003助手操作授權主聊天模式與臨時聊天)、[REQ-009](REQUIREMENTS_BACKLOG.md#req-009可選三角色討論與可展開觀點)。

| 聊天模式 | 可使用的背景 | 助手正式寫入 |
|---|---|---|
| 助手 | 本題相關、當前有效且獲授權的主聊天／孩子／記憶與來源 | 預設先確認；使用者選自動模式後，僅在有效授權內直接執行 |
| 只是聊天 | 保留同一主聊天背景；可搜索、解釋、比較及產生聊天文字 | 不建立正式文件、記憶、待辦或待確認卡片；不暗中切回助手 |
| 臨時聊天 | 獨立空白起步；只用當次內容及公共來源，不載入主聊天／孩子／私人記憶 | 不回寫主聊天、記憶或任務；正常退出清除項目控制範圍內的臨時內容 |

```text
你選聊天模式：助手／只是聊天／臨時聊天
                     ×
你選討論開關：不討論／明確開啟三角色討論

開討論 ≠ 切換模式 ≠ 擴大資料範圍 ≠ 批准操作
```

助手與只是聊天保留同一段對話及產生模式；切回助手不補做舊聊天。臨時聊天的晚到結果不能復活已清除內容；異常退出、遠端清除未確認及第三方保留限制須如實區分。

## 2. 主聊天：必要背景 → 模型 → 工具／專責 → 真結果

依據：[REQ-008](REQUIREMENTS_BACKLOG.md#req-008主聊天工具循環與按需專責代理)、[REQ-007](REQUIREMENTS_BACKLOG.md#req-007可追溯的分層記憶與按需召回)、[REQ-001](REQUIREMENTS_BACKLOG.md#req-001搜索優先的育兒資訊體驗與三類資料來源)。

```text
你的問題／交代
      │
      ▼
依聊天模式組裝本題「最小而足夠」的背景
  ├─ 穩定指引：身份、語氣、信任／私隱與工具規則
  ├─ Server 狀態：模式、目前對象、時間、能力、權限
  └─ 相關資料：對話、有效摘要、已確認條件、目前事項／來源
      │
      ▼
主聊天模型：理解問題、選擇下一步
      │
      ├─ 背景已足夠 ──────────────────────┐
      │                                   │
      ├─ 缺關鍵私人背景                    │
      │    → 按需讀相關記憶／歷史／原文    │
      │                                   │
      ├─ 需要公共依據                      │
      │    → 按問題選來源、搜索及讀原文    │
      │       ├─ 長期官方知識庫            │
      │       ├─ 時效資訊庫                │
      │       └─ 按需即時搜索              │
      │                                   │
      ├─ 清楚簡單操作                      │
      │    → 直接用業務工具〔見第 4 節〕   │
      │                                   │
      └─ 複雜操作／頁面／文件              │
           → 按需委派專責 Agent           │
              讀取 → 製作／操作 → 讀回    │
                → 開檔／渲染／必要修正    │
                → 真產物、版本、收據      │
                      │                   │
          工具／專責真結果                │
                      └→ 主模型繼續 ─────┤
                                          ▼
                                 準備可交付的回答
                                          │
                         程式校驗＋按需額外核對
                                          │
                                          ▼
正常主聊天回覆：答案、依據／限制、實際結果
  ＋確有相關需要時，補充溫和、可略過的盲點提醒
```

- 個人化回答先取得必要背景，不要求重述已可靠可用的條件，也不預載全份家庭檔案。具體選取欄位、優先序及容量是工程待校正項，不是每題固定帶齊的清單。
- 已有資料足夠便直接處理；只有會影響回答的缺口才補讀或補問。分清未載入、查無結果、取得失敗、已失效與容量省略；沒有記錄不等於沒有照顧。
- 日常需要／盲點發現不依賴三角色討論，不為湊提醒製造焦慮或每題列風險清單。必要急迫求助提示不等最後答案；固定官方求助入口獨立於主 Agent 是否調用工具。
- 額外核對按任務、實際內容、來源及產物成立，不是每答必叫 reviewer；有引用不自動等於必審，沒有引用亦不是免審證明。頁面／文件的內容核對與實際產物品質檢查分開。
- 公共三類來源按內容性質區分；即時搜索不強制整站建庫。外部查詢只帶必要條件，不附整段私人對話；官方依據、近期事件與社群經驗不能混為同等證據。

## 3. 可選三角色：真實互相回應，不是固定四站流水線

依據：[REQ-009](REQUIREMENTS_BACKLOG.md#req-009可選三角色討論與可展開觀點)。這三個是可見的 **AI 分析觀點**，不是將編製、reviewer、公共維護等工程職責換頭像，也不假稱真人專家加入。

```text
你明確選擇開啟討論
          │
          ▼
同一份本題相關、有效、已授權的初始背景
          │
          ├─────────────────┬─────────────────┐
          ▼                 ▼                 ▼
 育兒知識／經驗視角    新手家長視角    不同育兒方法視角
          │                 │                 │
          └───── 互相回應理由、疑問及取捨 ─────┘
                            │
                   按需用工具補讀／補證
              真結果回到討論，帶新證據再回應
                            │
         各發言先符合來源、披露及必要核對條件
                            │
                            ▼
           可展開的實際角色發言＋不同名稱／頭像
                你可觀看、收合或不觀看
                            │
                            ▼
                 主聊天保留原有最後回覆
          說清有用結論、分歧、來源及未解問題
```

- 未開啟就不暗中運行三角色；不開討論仍有正常回答及日常提醒。三角色共用初始背景，不各自先重讀全庫或生成一份摘要。
- **不新增摘要 Agent，不增加討論專用摘要模型呼叫或固定摘要收尾階段。**主聊天在正常回答中承接結論；按需技術壓縮仍屬第 5 節的另一件事。
- 各角色可回應已可披露發言及新增證據，不是互不相干的三段獨白；不強求共識、假分歧或固定輪數。觀點只改分析角度，不改工具、規則或授權。
- 角色同意、投票或重複引用不創造獨立證據、review 核准、正式事實或使用者同意。不能先披露無可靠依據的高風險主張，再靠最後回覆糾正。
- 收合／略過只是顯示選擇，不等於取消；明確要求停止才沿原取消契約處理。可見發言不是內部思考逐字稿、隱藏提示詞或私人 trace。

## 4. 保存與執行：內容合格、動作獲准，缺一不可

依據：[REQ-003](REQUIREMENTS_BACKLOG.md#req-003助手操作授權主聊天模式與臨時聊天)、[REQ-008](REQUIREMENTS_BACKLOG.md#req-008主聊天工具循環與按需專責代理)。本節適用於主聊天及所有專責工作；只是聊天／臨時聊天不進入正式寫入。

```text
助手提出新增／修改內容
  │
  ├─ 預設先形成待確認草稿，顯示目標與差異
  │    ├─ 取消 → 本草稿結束，不執行
  │    ├─ 修改 → 回到新版草稿，不能沿用舊確認
  │    └─ 確認 ────────────────────┐
  │                                │
  └─ 已選自動模式且本次在有效授權內 ─┤
                                   ▼
                 重核目標、版本、權限及必要內容檢查
                                   │
                                   ▼
                  業務工具正式執行 → 真收據／實際狀態
                                   │
                                   ▼
                  同一操作結果查回，不因失聯重做
```

待確認卡片與歷史沿同一「記錄與核對」；右上角只作快捷入口。自動模式不免除動作原本需要的額外批准；超範圍、撤權或目標不明便停止依賴的執行，依情況補問、請確認或說明限制。內容 review 通過不等於使用者批准保存；提醒／討論／技術摘要亦不自動成為記憶或待辦。

## 5. 背景維護與長工作：獨立接續，不拖住每次聊天

依據：[REQ-004](REQUIREMENTS_BACKLOG.md#req-004背景知識更新工作流與整本-pdf-自動處理)、[REQ-006](REQUIREMENTS_BACKLOG.md#req-006模組化來源庫共享匯入匯出與分類精細度治理)、[REQ-007](REQUIREMENTS_BACKLOG.md#req-007可追溯的分層記憶與按需召回)、[REQ-005](REQUIREMENTS_BACKLOG.md#req-005可調資源政策合理餘裕與累積資料可擴展)。

```text
公共知識維護〔不依賴家長開聊天〕
 已批准來源 → 排程查新／查變更 → 固定原文版本
   → 全文／整本 PDF 解析與覆蓋核對〔必要 OCR／vision〕
   → 只處理新增、變更及欠項；按需語義整理／獨立核對
   → 候選索引與檢索核對 → 完整版本發布 → 讀回驗證
   → 長期官方庫／時效庫供主聊天搜索

私人摘要／記憶維護〔與公共資料、權限及出資隔離〕
 新增／變更／失效事件 → 有界整理相關原訊息
   ├─ 技術摘要 → 保留來源、模式及覆蓋 → 承接對話
   └─ 記憶候選 → 第 4 節內容／授權條件 → 正式記憶
 更正／撤權／刪除 → 使受影響摘要、索引及快取失效

長對話／工具上下文〔不是討論專用摘要〕
 按集中政策需要壓縮 → 同一受控 gateway／原帳計量
   → 保留必要工具 call／result、原文位置、版本及收據
   → 需要時按原身份／位置補讀仍可用原文

各類長工作
 持久檢查點 → 從未完成處接續 → 真終態／部分結果
 unknown → 先查原工作／收據，不清零預算或盲目重送
```

長期官方資料定期檢查，時效資訊每天檢查；社群仍按需即時搜索。無變更且沒有欠項時不叫模型，不因重新啟動而重做成功成果。新增／變更且需語義判斷的公共成果須獨立語義審核；已驗純結構變更可依核准程式檢查契約處理，不能自行將醫療／安全意義降級。來源閱讀設定與版本可復用／按規則匯入匯出，但私人資料不混入公共來源包。

技術摘要不是已確認事實，候選不能冒充有效記憶；只聊內容可用於同一主聊天的承接摘要，不能藉背景整理變成助手操作。臨時內容不被主聊天背景吸收。壓縮不等於刪歷史、更新正式記憶或將 unknown 改成成功；已刪或失權內容不能從舊摘要復活。無依賴的一般回答不等待全庫整理。

## 6. 全圖共用保障與仍待決定的地方

依據：[REQ-002](REQUIREMENTS_BACKLOG.md#req-002agent-提速可見進度與分階段交付)、[REQ-005](REQUIREMENTS_BACKLOG.md#req-005可調資源政策合理餘裕與累積資料可擴展)、[REQ-008](REQUIREMENTS_BACKLOG.md#req-008主聊天工具循環與按需專責代理)、[REQ-009](REQUIREMENTS_BACKLOG.md#req-009可選三角色討論與可展開觀點)。

- **程式保障常設，額外模型審核按需：**Server 強制身份／孩子／模式／可見範圍、工具 allowlist、參數、來源／產物版本、必要確認、防重、取消／期限與原結果查回，不靠模型自報已批准。
- **一份原工作總帳：**主聊天、專責、討論、工具、必要 review、修正、壓縮及重試共用原 root 累積用量；獨立公共背景用原公共工作帳，不借私人資料或 key。`softBudgetRatio = 0.25` 是已確認可調預設，不是花費目標、硬停止線或新開支批准。
- **真進度與真結果：**顯示實際來源、角色及工作狀態；已符合自身交付條件的部分可先交付。斷線查原 run，不把已保存結果因文字收尾失敗抹掉，也不把入列／已派出當完成。
- **最小追蹤：**只記受控版本、涵蓋／選取／省略原因、角色／階段及用量 metadata，不記完整家庭正文、查詢、prompt 或私人 trace；記錄存在不代表模型已理解。

| 已確認方向 | 不在本圖自行定案的細節 |
|---|---|
| 主聊天工具循環、按需專責、普通聊天亦能發現需要／盲點 | 首輪背景的精確欄位、優先序與容量；不把舊實作的訊息數當最終規格 |
| 可選三個起始觀點、共同背景、真實互相回應、正常主聊天最後回覆 | 顯示名稱／頭像、發言次序、串行／並行、回合及結束策略、保存與模式清理接點 |
| 必要內容／來源／產物核對；不是每答必叫 reviewer | 詳細觸發表、核對交付單位及可復用證據；「所有高風險建議或重要記憶變更一律額外專家審核」不是已批准的普遍規則 |
| 有界執行、同帳、原操作恢復及按需技術壓縮 | 實際模型／工具／時間／並行上限、政策在途生效與品質／成本門檻；沿既有模型／付款設定，不因角色增加另選新模型或擴權 |

本文件只供核對目標流程，不把畫出箭嘴、需求確認、文件合併或局部工程證據當成相關能力已實作、驗收或部署。
