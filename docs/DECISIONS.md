## ADR-008 — Server 唯一權威與五階段局部修訂

- 日期／狀態：2026-09-22，已確認；依據：使用者本輪確認的 Server 架構及五階段調整，於 DOC-R02 落盤；只修改文件與專案開發設定，不啟動產品實現。
- 原因：手機／瀏覽器主庫、離線 outbox 及手機中繼增加三種儲存、任務交接與同步的複雜度，也無法承擔 P2 關閉瀏覽器後持續執行的主動照顧流程。
- 決定：Server 是唯一業務資料權威及 Agent 執行端，PostgreSQL 持久儲存；Web／Android 是同一服務的在線客戶端。正式替代手機／瀏覽器業務主庫、SQLite／IndexedDB 業務持久化、離線 outbox、自動離線重放及手機 WSS 資料中繼。斷線只在當前頁面保留未提交表單／照片，明確標示未保存並由使用者手動重試；重新整理／關閉前提示可能丟失，不承諾跨關閉草稿恢復。Server 確認前不得顯示保存成功。
- 邊界：只實現育伴港，共享 TypeScript 業務與薄平台 adapter，必要 port 隨功能建立；核心 Server 分層由 [ARCHITECTURE §3.1](ARCHITECTURE.md#section-3-1) 維護，不預建通用平台、第二領域或空框架。

| 階段 | 本次確認的門檻與調整 |
|---|---|
| P1 | 最小 Server、PostgreSQL、Better Auth 身份及資料隔離先行；Web 孩子／文字記錄／聊天與真 Gemini 形成合成資料閉環後，完成 Server 儲存加密、最低加密備份／還原及驗收。組員可開啟的試玩網址仍是 P1 完成要求，並非現況；S06-W03 在 S03-W01 前，S06-W01 保持最小 AI proxy 職責 |
| P2 | 比賽必達：家庭權限、持久 worker、完整 AI orchestration、長期記憶、Web 照片、Web Push＋Telegram 及預授權找人 fallback；按已授權對象／條件執行，不逐次確認，每次執行檢查當前授權及撤權。任務、投遞、閱讀與完成分開，重試不重複發送。社交來源由使用者主動分享公開更新，不自動讀取私密 feed |
| P3 | Android 在線客戶端、FCM、語音／相機及平台適配，Web／Android 共用同一 Server；跨端一致性、撤權、失敗與真機驗收隨功能完成，不重新建立手機業務主庫 |
| P4 | 自選相容 Server API；Windows Docker Compose 少步部署，接受 Docker／WSL 前置；裝置配對及臨時會話只作授權、不作中繼；Server 搬遷、災備、保留新寫入的 rollback，完整知識／報告及最終交付 |
| P5 | 可選增值；不承接 P1–P4 必要驗收，不預建未來平台 |

## ADR-009 — 有界工作上下文、測試及子代理政策

> 歷史身份：下方當時的代理數量、模型／effort、工具與閱讀入口已由後續使用者指示替代。現行調度只看 [AGENTS#models](../AGENTS.md#models)，runtime 值只看 [.codex/config.toml](../.codex/config.toml) 及角色檔；文件收斂見 [ADR-016](#adr-016)。不照歷史值開代理，亦不改寫原決策理由。

- 日期／狀態：2026-09-22，已確認；依據：使用者確認最新開發政策。權威規則在 [AGENTS](../AGENTS.md#models) 及 [PLAN 驗證制度](../PLAN.md#verification)，本 ADR 記錄理由與替代範圍。
- 原因：避免完整歷史反覆載入、過度委派、碎片訊息與無根因重試，控制驗證成本，同時保留必要驗收及人工結果的真實邊界。
- 上下文與記錄：先 STATUS，再 PLAN 當前包；已有結論先復用，足夠證據即停止。WORKLOG 日常禁止全讀，只讀模板／相關 LOG／追加所需尾部，既有位元組、連結及格式不回寫；只有實質工作包狀態、實現／驗收、重要失敗決策或正式里程碑才追加。普通 Git、格式及臨時檢查不記 LOG。歸檔仍先索引再指定內容，移入或 archived-in-place 同包更新索引；S00 JSON 唯一原位。
- 分工：主模型 UI 自選 Astra／Sol，不固定或降級。長期子代理只用 Luna Max 唯讀調查與 Sol High（可 High／Xhigh／Max）有界實現；禁止 Terra／Astra，使用者明確指定優先，當輪例外不構成永久許可。Luna 不寫檔、不執行 workspace 寫入或架構決策；所有子代理禁止再 spawn。主模型做簡單搜尋／單檔工作，並負責架構、複雜實現、衝突、整合 review 及最終驗收。
- 限額與交接：每包同時及累計最多 3 Luna＋2 Sol；重啟／恢復／替代啟動均計入，達限先整合不追加。主模型先完整拆分，明列目標、範圍、路徑、約束、禁止事項、輸出與證據，一次下達；明確角色／模型／effort 與 `fork_turns="none"`。不輪詢進度、不用 `send_message` 追問／重複／零碎補上下文；follow-up 只補會阻塞的關鍵證據。每輪收齊後統一整合，未整合不追加同類。
- 實際配置：只改專案 `.codex/config.toml` 與角色檔，預設子模型 Sol、effort High、總並發硬上限 5；`explorer` Luna Max／readonly，`worker` 固定 Sol 而不固定 effort。角色數及累計限額屬行為規則，不聲稱 TOML 已提供這些額外硬限制；不改全局。配置檔不證明當前 runtime 或唯讀 sandbox 已生效，必須核對實際啟動結果。
- 驗證政策：預設只執行修改必要的輕量檢查及公開輸入／輸出單元測試；integration、E2E、真機、真實服務、深度／全量回歸須先交代原因、範圍、成本，由使用者決定。未批准的必要驗收保留「待驗收」，不降低完成門檻。可合併的讀取／搜尋／修改／檢查批量做；連續兩輪修改、驗證、再修改仍失敗，先整理根因、失敗證據及下一方案。
- 分支／範圍：可獨立驗收工作包（包括文件包）是分支與合併單位，依賴其成果須等 review／合併，不受整個父 Sxx 完成鎖約束；領域解耦按需建立，不增加通用平台或空框架。
- 替代／驗證：替代先前 AGENTS 的 Sol Medium、通常容許 Astra 實現子代理、最多四代理及未區分測試成本的規則；ADR-004／005 的歷史保留。DOC-R02 只核對政策、專案設定與文件一致性，當前 runtime 未核對部分及未執行驗收須如實報告。

## ADR-013 — 近期來源先限組內試用

- 日期／狀態：2026-09-28，使用者確認「先限組內試用，公開版保留關閉」。
- 原因：S10-W02 核對 [CHP 重要告示](https://www.chp.gov.hk/tc/static/24027.html)及 [RTHK 知識產權告示](https://www.rthk.hk/copyright/preview/index.html)，其一般准許範圍主要為個人／機構非商業內部使用；RSS 可讀及訂閱說明不足以確認公開比賽再發布權利。不推定有額外的公開內容授權。
- 決定：CHP／RTHK 的來源觀察、每日更新及檢索只供組內非商業試用。公開 store 預設排除這些來源，操作者的 internal audience 不是模型／客戶端可選權限。取得適用授權或核對可公開復用的替代來源後，另按實際變更開放；不因此停止官方穩定知識、worker、日期／分類／版本及增量向量機制。
- 保留／影響：局部調整 REQ-5-6-09 及 S10-W02／P2 公開展示範圍。近期資訊仍不得形成家庭事實、照護規則或任務；FHS 非商業知識範圍及 ADK／RAG 總架構不變。S16／S17 明示組內已驗與公開未開放，不把內容使用範圍選擇當作技術驗收通過。
- 替代來源調查：香港政府新聞網的 RSS／版權資料未清楚涵蓋本次公開展示；HKFP 的官方重用條款及 feed 未能核實。沒有因非牟利身份或可抓取而自行改選，也不繼續擴大成新聞平台研究。

## ADR-014 — 家長自訂私人資料來源

- 日期／狀態：2026-09-29，使用者明確要求家長可設定自己的資料來源，包括訂閱／付費資源；本次在 S12-W04 落實，新增保存接線仍待集中驗收。
- 決定：復用私人分享來源、加密保存、受限 HTTPS transport、明確 AI 提取及家庭確認流程。家長自行提供名稱、網址、備註／日期及正文，或一次性取得公開可直接訪問的 HTML；需登入內容由家長提供，不代登入或保存網站憑據。來源按本人及目前孩子隔離，URL-only 不表示已取得或分析。
- 使用範圍：此功能讓家長管理自己的私人材料，不把使用者貼上連結視為額外授權聲明，也不據此擴大產品的公共內容庫。實際可採用方式仍依各來源與家長的使用權限；不要求所有私人來源都有公開再發布授權。
- 保留／限制：ADR-013 的 CHP／RTHK 公共檢索限制維持。私人來源不自動進公共 RAG、家庭事實、任務或外發；AI 提取只讀家長選取的正文，私有 URL／備註不傳模型。完整帳號連接、背景私人訂閱、PDF 解析及跨孩子來源管理未在這次實作，不把快照入口宣稱為完整連接器。
- 驗證：只加一項私人輸入／HTML／客戶端邊界檢查，並重用一項既有 transport 檢查；023 遷移、本人隔離及真接線列集中缺項，無新增模型、真網站或 E2E 呼叫。

## ADR-018 — P2 完整 Agent 與邀請制穩定單人 Web 服務

## ADR-019 — Firestore 與集中雲端低用量服務

- 日期／狀態：2026-10-08，使用者定案，**文件已採納，遷移未實作／未驗證**。依遠端 master 0c22180 及實際 SQL／store／worker 盤點，保留 P2-A01～A08 成果；#140 修正與衝突另處置，不把 draft 當已合併。
- 決定：集中邀請制、本人空間；Firestore Standard Native、私有 Cloud Storage、Cloud Run request-based／min 0、Firebase Hosting、Firebase Authentication，Tasks＋Scheduler＋持久台帳。明確排除 SQL Connect／Cloud SQL 及額外常駐搜尋叢集，不重寫 ADK、Prompt Pack 或前端。
- 理由／取捨：降低低流量固定費，不把 Firebase 當免費。SQL join／savepoint／FK／trigger、交易內 pg-boss 及 pgvector 不能直接搬 API，須重做有界查詢／索引、read-first 交易／收據／outbox、清理及喚醒接線。Firestore Standard 無全文搜尋，補有界公共分詞／n-gram 候選並保留正文能力；原生向量承接兼容的 1024 維向量，免不必要重算。
- 身份決定：有 MIT 的 [Better Auth Firestore 社群 adapter](https://github.com/yultyyev/better-auth-firestore)，保留原方案並非技術上不可能；但增加 adapter、寄信及跨身份／業務一致性維護。使用者選 Firebase Auth，接受 [認證資料在美國處理](https://firebase.google.com/support/privacy)，業務／運算預設香港。UID 保留，STANDARD_SCRYPT／salt／NFKC 要實測，舊 session 作廢、不相容重設；產品准入／成員及逐裝置會話仍由 Server 管理。
- 不變條件：原 ID／版本／密文／收據與權限、來源及確認語義保留。Server IAM 不代替家庭授權；私人內容不進公共索引。Tasks 不是 exactly-once，未知模型／通知結果不盲重做；Hosting 60 秒轉送以持久 run 的 202 受理承接，不提高模型配額。來源新版以含義核對，不以 hash 即發布。
- 恢復：短暫停寫、不長期雙寫；daily backup 14 天，附件 soft-delete 7 天另加配對副本覆蓋全部恢復期。刪除 journal 獨立、不可覆寫、不隨 DB 還原；隔離還原先重放刪除、核 Auth／附件、換 epoch 才開放。新環境產生寫入後須反向同步才能回退，Auth／撤銷不可回舊快照。
- 替代範圍：替代 ADR-018 的 Better Auth／單 VM 服務交付及 SQL／pg-boss 作後續必要依賴；保留其全部 Agent 成果及安全門檻。ADR-008 與原自部署方向在本輪由代管服務取代，原 Sxx／P3／P4 錨點與延後範圍、歷史 ADR／WORKLOG 不回寫。A09 的 VM／SMTP 專項交付被替代，有效修正及未通過成果仍承接。
- 採用門檻：先 F02 有界真雲端合成切片，覆蓋權限、交易／防重、縮零／重投遞、引用、附件與刪除還原；不能只憑 Emulator。再搬全功能、對帳及反向回退、F08 正式 Agent 交付。依賴／責任／唯一入口見 [PLAN](../PLAN.md#p2-firestore-migration)，契約見 [架構](ARCHITECTURE.md#firestore-target)，官方依據及未驗點見 [TECH_REUSE](TECH_REUSE.md#firestore-dependency-audit)。
- 授權邊界：本輪只文件；不建付費資源／改正式資料／遷移／部署／續期。F02 資源與成本、F08 維護窗口及實測預算仍須核准。原配額、通知對象與內容不因計劃擴大，價格推算不當已付費或性能證據。

- 保留邊界：ADR-022 的乾淨起點、舊備份保留、新資料不可回退 SQL 舊快照、Firebase 相容版本回退、獨立刪除日誌及配對恢復不變。家庭／私人／孩子隔離、收據、changes、unknown 與有效來源／版本保持；正式運行不得連 SQL 或靜默回退。延後角色不等於移除現有產品能力。
- 成本：VM 固定費仍在；本次主要減少 PostgreSQL 維運及再次改架構／重驗成本，不保證 Firebase 免費或總月費下降。沿保存的香港 SKU 估算與實際費用範圍，後續按讀寫／向量／附件／備份／模型與 VM 合計量測，不以新 run 或新服務繞配額。
- 替代與承接：取代 ADR-019／022 的全面 Firebase 網站／運算遷移、縮零及最後切前端要求；將 ADR-023 未定的 VM 選擇定為保留，ADR-021 的暫緩明確承接至 P3。保留原 ADR／WORKLOG／失敗內容；唯一工作順序與狀態見 [PLAN](../PLAN.md#p2-firestore-migration)，本次合併後停下，不啟動實作。

## ADR-025 — 先完成資料庫替換，再交付受邀用戶

- 日期／狀態：2026-10-12，依使用者最新指示「先完全遷移掉數據庫」「數據不一定需要保留」「受邀用戶能用應該排在數據庫更新後」。這是執行次序調整，不是遷移已完成。
- 決定：先完成全部既有資料域、知識檢索及背景台帳的 Firestore 替換，退出正式 SQL 組裝／啟動／依賴／備份；使用已存在的 GCP 香港 Firestore，不另外建站。F03～F07 核對必要資料與服務接點，F08 再集中完成受邀用戶、真 Agent 成果及原站交付。
- 資料與成本：允許乾淨起點，舊測試資料、帳號、密碼及私人內容搬遷／對帳不作前置。已有官方知識與相容向量可按效益復用，不為舊資料另造搬遷器。舊資料／備份暫留，本次沒有執行刪除；新資料的權限、防重、持久化、刪除及必要恢復仍保留。
- 保留架構：沿用 ADR-024 的原 VM／Compose／Caddy、前端、ADK、Firebase Auth／Storage／Tasks 及共同業務接口；容許維護停站，不維持雙寫或一套額外舊站。其他三角色仍在 P3，無須重新改技術棧。
- 替代範圍：取代 ADR-024 的「F03 首次聊天可用即更新原站」及逐資料包正式上線門檻；不取消 F08 受邀用戶成果，也不把局部資料測試當成完整 P2 已驗。先完成資料庫工作能減少重複部署及用戶流程驗收；不宣稱尚未量測的節省幅度。
- 驗證／授權：各包只核變動的必要資料路徑，真模型／瀏覽器及受邀體驗延後集中驗證；原失敗保留，不自動重跑已停止的付費批次。雲端資源、外發、費用與私有檔案傳送仍依有效授權，唯一當前入口見 [PLAN](../PLAN.md#active)。

## ADR-026 — 每日原生備份與受控還原分開

- 日期／決定：2026-10-13，使用者確認採用 Firestore 原生每日備份、保留 14 天；本輪新增備份／必要還原增量費用上限 US$1。排程持續計費，這個金額不是 GCP 硬停費功能；後續規模／預算變更另核。
- 原因：既有配對匯出工具須停站及輪換工作世代，適合作受控部署／恢復，不能每日照搬。原生排程不影響日常讀寫，確切備份時間由平台決定；設定成功、首份備份可用及實際還原是不同證據。
- 邊界：保留私有 Storage、應用加密及獨立永久刪除日誌。原生備份不含附件、Auth、Rules 或 TTL。快照中的 generation／hash 與至少 14 天的附件復原期配對；不把仍在 soft-delete 的內容視為可以恢復，先查獨立日誌排除永久刪除。舊獨立配對副本、hold、期限及失敗證據保留。
- 還原：以原生來歷及 operation 核對全新隔離資料庫，再復用現有身份／刪除重放、epoch、原操作及分批套用流程。來源實際停機／暫停仍是還原門檻；新庫不掛 API／worker、不自動切流量。遇不完整附件、未知操作、失效身份或缺失清理證據保持關閉。
- 替代範圍：僅取代每日必須使用停站配對匯出的方法；不降低 14 天資料／附件保護、刪除不可復活及恢復驗收。現行進度見 [F08](../PLAN.md#p2-f08)。[原生備份](https://docs.cloud.google.com/firestore/native/docs/backups)、[原生還原](https://docs.cloud.google.com/firestore/docs/reference/rest/v1/projects.databases/restore)、[附件精確恢復](https://docs.cloud.google.com/storage/docs/json_api/v1/objects/restore)。
