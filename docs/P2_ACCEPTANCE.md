### 失敗原因局部核對與修正

RTHK 官方列出的 HTTPS RSS 位址實際轉址至另一主機的 HTTP 位址，因而被現有安全邊界拒絕。固定來源改用已核對的 `https://rthk9.rthk.hk/rthk/news/rss/c_expressnews_clocal.xml`，一次正式 adapter 補驗取得並解析 20 項；保留 HTTPS／同主機、組內使用及不保存正文的限制。只新增失敗來源的一次診斷 GET、兩次標頭 HEAD 及一次修正取回，沒有重跑五個成功來源、資料庫／cron 或模型。

Firefox 的 Windows SideBySide 33 事件指向 mozglue 私有 assembly 無法解析；exe／DLL 的 CRC32 與官方固定版本 ZIP 清單相同，兩者均有內嵌 manifest，官方包也沒有獨立 manifest。CRC32 僅核對下載／解壓一致性，不能當作簽署證據。只做兩次 `-version` 啟動診斷，沒有產品情景、重裝、改安全設定或修改瀏覽器 binary；Windows 根因尚未完全確定，Firefox 仍待驗。

另以既有還原庫的一份合成近期來源補核必要隔離：公開模式不能發布／取回，組內模式可取回；最後成功核對時間超過 24 小時後亦被排除。16 次業務呼叫、一個明示合成向量，零真 embedding／模型／外網／家庭寫入；結束停用該合成來源，worker 保持暫停。
