<a id="design-intent"></a>
## Astra 原方案的核心設計思路

| 思路 | 設計意圖及後續使用方式 |
| --- | --- |
| 先把三張旗艦畫面做完整 | 首頁、完整答案連來源、記錄詳情先建立共同品質，再推廣至其他頁；以一個完整閱讀切片起步，避免同時改十多頁而各用一套規則 |
| 有來源的育兒問答成為主角 | 首頁及導航清楚表達家長能問問題、看懂答案與下一步；記錄及確認支持這個體驗，首次使用按需要補資料 |
| 明亮、準確、有香港溫度 | 青色界定品牌、黃色集中 Agent 主入口、海旁親子插畫建立辨識；答案好讀，核對工具精準，留白服務內容主次 |
| 閱讀與操作有不同層級 | 普通答案用連續正文，需確認的事項用操作卡；同類資訊貼近、不同類用線分開，避免所有內容都被包成同等份量的卡片 |
| 來源核對是一段完整閱讀旅程 | 從引用句到對應來源，再回原句；發布者、引用及適用資訊優先，版本／hash 等技術資料次層，追溯資料仍完整保留 |
| 一個重點及一個有用次欄 | 首頁突出真正值得處理的一件事；工作區只保留當下有用的次欄，避免孩子、記錄、操作摘要重複佔位；重點承接權威投影 |
| 完成互動比加裝飾更重要 | 焦點、鍵盤、錯誤修正、閱讀返回、草稿及未知操作延續一併設計；正常、等待、失敗、未知及撤權各自清楚呈現 |
| 在現有能力上逐步精修 | 沿既有框架、controller 及 adapter，少量擴充字級／密度／surface；按可用 pane 重排、觸控密度獨立，有實際重用才抽 helper |
| 設計、實作、接線分層驗收 | 先定構圖與 view contract，再做共用基礎、閱讀切片、逐頁推廣及正式 adapter；預覽品質、真資料操作和原生效果各留實際證據 |

這些是原方案的設計意圖摘要；各章另記需要更新、部分採納、已具備及延後的判定。後續元件改動應連同相關版面、動態與互動核對，沿用這些思路，而不是只修單一截圖。

## 首頁：採納主次方向，保留最新手機行為

| 文件建議 | 判定及處理 |
| --- | --- |
| 有來源的育兒問答成為主角 | 需要更新定位。SPEC 的核心包含育兒問答；現桌面主句偏向「照顧整理空間」，可調整主次，但首頁仍不放提問欄或快速提問。問答入口沿既有 Agent 導航 |
| 單一「今天值得處理的一件事」 | 採納方向。優先承接待查操作、已授權任務／預約、適用成長提示或安靜空狀態；取得失敗不能顯示成「沒有事項」。尚未有足夠 Home view model，先定投影，不在首頁另建業務 store 或每日模型生成 |
| 主區／右欄的孩子、記錄、最近操作不重複 | 需要減量，但要按路由及可用空間挑選用途，保留能解釋當前上下文的資訊。不是刪去所有右欄或所有孩子背景 |
| 沒有待確認內容的卡片縮小 | 建議採納。空狀態使用簡短行／必要入口，不與真正有事項的卡片佔同等份量 |
| 手機 Today highlight 去掉重複巢狀卡片／裝飾 | 建議採納。保留重點和必要下一步，不以星形、記錄數量或 checklist 製造重要性 |
| 桌面 208 高、60／40、radius 16、padding 16 | 首輪比較值，並非規範。採納「文字有主次、完整圖片、自然留白」；實際尺寸要看已選構圖、長文及字體放大 |
| 手機 168 高及較清楚的字級 | 保留自然高度／minimum 的方向。#77 已有 26／16／14 手機問候文字、右邊完整圖片、首登三秒後收起及穩定結尾；不固定裁切高度，也不重播每次換頁 |
| 焦點依操作、任務、成長、none、unavailable 分類 | 需要真投影依賴。可用薄 view model／callback，順序及權限由既有業務決定；none 與 unavailable 分開。不新造任務終態、健康分數或「照顧完成」推論 |
| 顯示預約日期／數量、解釋 why now | 有真快照才顯示；未知不能補值，不從記錄缺少推斷家長疏忽。成長提示需適用性及必要來源 |
| 首次進入先問、資料按需要補充 | 採納產品方向。已有孩子即可開始問答，引導可選；沒有孩子沿最少必要建立流程，不增加匿名模式 |
| Guide 狀態不能當孩子事實或授權 | 現有方向正確，保留。Guide 並非硬性問答 gate；只需改善問答入口與引導的主次，不重做權限系統 |

對應入口：[HomeDashboard](src/components/HomeDashboard.tsx)、[MobileHomeDashboard](src/components/MobileHomeDashboard.tsx)、[首頁投影](src/view-model.ts)。首頁精修需要內容主次先定，不能將外部示例直接作正式「今日重點」。

## 對話：閱讀面和輸入區一起改善

| 文件建議 | 判定及處理 |
| --- | --- |
| 普通回答用連續正文；可確認事項另作操作卡 | 建議採納。保持兩類內容的用途，不讓普通段落全部變成同等白卡。保留使用者訊息在右、無頭像、每訊息來源、穩定 message id |
| 答案 16／26、工具 14／22、閱讀上限 880 | 合理比較起點，尚未確認數值。只調閱讀區及相關工具，composer 與正文同欄；不把工作台／全站都縮到 880 |
| 聚焦、有草稿或鍵盤時收起建議 | 建議採納。已觀察草稿輸入後建議仍佔空間，composer 高約 216／220 px。只收建議區，不能卸載 TextInput、附件或丟失草稿。可由使用者再開；未知是否新對話時預設收起 |
| 純 Enter 換行，Ctrl／Cmd+Enter 可送出 | 換行保留；快捷鍵屬選配。若實作，先處理 IME composition、平台鍵盤及避免重複送出，不只綁一個 keydown |
| 完整回覆收到便一次顯示 | 採納，已有預览串流能力不等於正式逐字資料已交付。正式完整回覆不要用計時器假裝流式；真 stream／cancel／history cursor 另依正式能力接線 |
| 思考、工具、停止和未知狀態 | 現有共用 ChatMessage／Timeline 已有公開過程、增量、停止、失敗／unknown／待確認投影，保留。顯示工具名稱、狀態及安全公開摘要，不展示或捏造內部思維鏈 |
| 長對話從底部保留最近，再展開較早記錄 | 已具備預覽顯示及錨點能力，不重建。保留 40／24 px 緩衝、懸浮回到最新、閱讀暫停及各訊息獨立狀態；完整歷史仍依正式 API |
| 已載入孩子背景與回答使用資料分清 | 必須保持。載入背景不代表模型真的採用；「本次使用」只能來自實際 metadata，不由前端推論 |
| 三歲共讀／FHS 答案例子 | 只作內容與閱讀示意。不得抄入正式答案或當已發布知識；真正引入仍經既有來源及版本發布流程 |
| 空對話問題示例 | 可採納小型引導，但要有已發布來源及適用情境；點擊只預填空白草稿，原草稿不覆蓋、不自動送出，不把問題變成已確認事實／任務 |

## 來源：採納閱讀優先及返回原句，完整保留追溯

| 文件建議 | 判定及處理 |
| --- | --- |
| 每訊息只有底部一組來源 | 已具備，保留。無淺綠底板、來源間細線、多來源橫向捲動、同項再按收起及正文數字瞬間定位都沿用 |
| 來源詳情先看發布者、標題、引用、適用範圍、日期及原文 | 建議採納。現有順序把版本與核對放在日期前，原文入口較後；閱讀資料優先，技術資料放次層 |
| 版本、hash、核對、讀取時間及歷史收於技術區 | 採納層級方向，不能刪 metadata。原始版本／checksum 仍完整可複製，歷史依據不被新版本覆蓋；章節、日期和技術資訊用貼近與細線分組 |
| 從來源返回原引用句 | 建議新增。保存 message id、來源 id、引用實例 id／可用焦點錨點；同來源被引用多次要返回剛按的那一次。跳轉與返回均即時，不自動打開面板或重啟跟隨 |
| 保留原閱讀位置、已載入訊息及 scope 清理 | 必須與返回流程一併做。必要時僅恢復已載入訊息；不自動追取更早游標。身份／孩子變更及卸載清掉過期錨點 |
| 面板按鈕形式看似 tabs | 保留視覺、調整語意。可以全收起的來源是 disclosure group；不能套用必須始終有選中面板的真 Tabs 行為 |
| 缺少 publishedDate／validUntil | publishedDate 與 fetchedAt 分開；缺日期明示未提供，沒有 validUntil 不代表永遠有效。即時資訊、長期指引及歷史快照分清 |
| 無來源／純操作的狀態 | 真 metadata 有原因才說明；空陣列本身不能推斷檢索失敗原因。純操作可無來源，現有 sources 可選方向正確 |
| 不做可信度百分比或「官方認證」 | 採納。真實發布者、版本及適用資訊已足夠，不用分數或徽章冒充權威背書 |
| `paragraphs/citationIds` 可直接復用 | 文件現況描述需更正：目前 `ChatMessageView` 是 text 加 sources，`frontend/src` 沒有這兩個欄位。已有明示引用數字的呈現可復用，正式逐段映射待主聊天；不能假設接口已存在或從中文正文猜引用依據 |

來源不是要移到中央 Dialog，亦不加第二份清單。返回引用錨點屬閱讀 UI；正式引用識別、發布版本、實際使用資料仍由正式投影提供。

| 孩子稱呼長度 | 正式 Family 的 UTF-16 `.length` 與 Server code point 80 仍須一致；隔離前端已按 code point 驗證，不重修前端 |
| 瀏覽器返回保護 | 既有證據只涵蓋 Edge 可取消 Navigation API。unsupported／不可取消 traversal 仍有缺口，重新載入／系統關閉也沒有私人草稿持久恢復承諾 |

正式 adapters 同時要沿權威能力處理來源映射、更早 history cursor、真 stream／cancel、費用及事項導航目標；不能以本地合成 UI 代替接線完成。使用者普通換頁保留草稿，身份／孩子變更、撤權及晚結果清理保持各自邊界。
