DESIGN NOTES

把下一步說清楚，
不替資料下保證。

這是合成、可操作的設計候選。所有按鈕都只影響本機示例；沒有真實重新載入、導航、寫入、API 或模型呼叫。未發佈到正式產品。

兩種資訊架構

  • A · 一頁恢復卡：先給一個清楚的主操作，聊天頁有次要返回入口；故障參考可展開。適合想快速繼續的人。
  • B · 恢復導覽台：先選意圖，再看其解釋與行動。重新顯示、返回與故障參考各有獨立面板，讀取較有層次，但多一步選擇。

兩版共用同一筆合成 callback。切換 A/B 不會建立第二次重試，也不會清掉等待狀態。

試用步驟

  1. 按「重新顯示頁面」，確認等候時再按也只受理一次。
  2. 等待期間換到另一版，查看下方 callback 次數仍相同。
  3. 在合成控制台按「拒絕」，再重新嘗試並按「完成」。完成只代表本機 callback 結束。
  4. 重試等待時選「新的全域故障」，再按「完成舊 callback」。新畫面不應被舊結果取代。
  5. 試用 B 的故障參考及聊天返回面板；全域故障沒有返回首頁入口。

來源契約

以 固定版本 RouteFeedback 與 安全參考 helper 為基礎。master 於 2026-11-06 查得同一 commit；這是時間點記錄，不表示永遠最新。

Router 提供 error/retry，原 UI 持有 retrying。root 和 chat 各自有 ErrorBoundary/SuspenseFallback；chat 的返回首頁直接呼叫 router.replace。原 helper 僅容許錯誤類別及最多三組數字位置。本候選 helper 只移除了 TypeScript 型別，其餘內容相同；畫面與合成 authority 則為自寫 adapter。

沒有直接提交呼叫，不代表整條重新掛載鏈沒有副作用。root 可能重建 provider，後代 effect 可能重新執行。草稿、未知結果、原收據及返回首頁守衛都需要真故障層級驗收，不能由這個候選推出保存保證。

研究與採拒

  • Expo Router 錯誤處理文件：讀取 nested boundary、retry 與 Suspense 的版本說明，採保留各自邊界。拒絕照搬 raw error.message 範例，不用新文件推定本專案 SDK 行為。
  • react-error-boundary GitHub README：讀取 reset/render 與捕獲範圍說明，採「重新渲染不等於原操作恢復」的區分。倉庫標示 MIT，但沒有複製其程式、美術或安裝套件。
  • W3C WCAG 2.4.3 Focus Order：讀取意圖與動態焦點說明，採自然閱讀順序、不由晚到結果搶回外部焦點。沒有將 DOM 檢查當作完整 WCAG 驗收。

以上均為 2026-11-06 取得的文字來源，不是視覺瀏覽或第三方素材。原創 CSS、系統字型，沒有第三方插圖。

已驗與尚未驗

RR01-F01 修復候選：B 的重試完成只更新同一筆合成結果，不再取代目前選擇的故障參考或返回面板。沒有另啟重試；完成後，聊天頁仍可受理一次本機返回意圖，全域頁沒有此入口。A 的完成頁保留。本輪修復仍待獨立複審，不代表真實頁面恢復或離頁守衛批准。

已驗：安全 helper、合成 retry admission／reentry／拒絕／退休晚到、兩 IA 及頁面控制的實際 JSDOM 事件、當前焦點與同步焦點改向、合成 pagehide 事件處理；單點反例可抓出重複受理及原始錯誤洩漏。

尚未驗：真正 React/Expo ErrorBoundary、完整 ProductionProvider／owner、重新掛載 effect、原操作保存、離頁守衛、原生設備、真瀏覽器、320px／200% zoom 實際排版、鍵盤／觸控／讀屏、BFcache 實際往返、完整 repo 型別與測試。這裡沒有以合成通過代填這些項目。

採用時保留什麼

  1. 先挑資訊架構；保留 root/chat 原 boundary 位置及 Router error/retry 合約。
  2. 只移植排版與安全說明，不把本機合成 authority 換成正式寫入 owner。
  3. 原系統故障測試分 root 與 chat；記錄 owner identity、pending/unknown operation、transport 次數與草稿狀態。
  4. 另核返回首頁 guard、重試拒絕／同步重入、退休晚到、瀏覽器焦點與讀屏。完成前不宣稱資料恢復。
