# Capability 與工具契約

本包定義語義及模型行為，**沒有宣告任何產品工具已存在**。可用工具只以本次 Server 提供的正式宣告為準；以下能力名稱是分類，不是可直接呼叫的方法或路由。

## 邊界映射

| 能力語義 | 現行責任接口 | 模型可做甚麼 | 程式必須做甚麼 |
|---|---|---|---|
| 讀取相關記錄／記憶、提交確認候選 | `DataStore` | 提出有範圍的讀取／草稿／更正要求 | 身份、私人／共享授權、版本、確認及權威寫入 |
| 取得附件與解析輸入 | `AttachmentStore`、`ModelGateway` | 引用實際可見內容，提取候選及不確定處 | 存取權、類型／容量、hash、傳輸與解析狀態、刪除 |
| 查詢已發布知識 | `KnowledgeRetriever` | 按類別／適用範圍查詢並引用支持片段 | 來源清單、發布／停用、日期、快取及過濾 |
| 任務建議／變更／跟進 | `TaskExecutor` | 提議目標、對象、時機、理由、缺項 | 授權、候選資格、時間計算、終態、租約、冪等、有限重試 |
| 外發及核對投遞 | `NotificationGateway` 配合 `TaskExecutor` | 生成授權範圍內的內容／fallback 建議 | 當前授權、有效綁定、原投遞核對、回執、投遞台帳 |
| 在線確認與版本核對 | `SyncEngine` | 要求核對原操作，不假稱保存 | `opId`、`baseVersion`、`storageEpoch`、實際確認與衝突 |

沿用 [API 接口](../../docs/API.md#section-3-3)；沒有新增通用工具服務或 plugin registry。

## 本次能力宣告應包含

| 語義 | 要求 |
|---|---|
| 識別／版本 | 本次實際 operation 名稱、契約版本、對應能力與用途；只由可信部署程式提供 |
| 可用性 | 可用、未接通、停用、暫時不可用或不相容；存在於文件不等於 enabled |
| 輸入／輸出 | 實際參數及結果 schema、必填資料、可用未知表示、來源參照；不得以任意文字當工具批准 |
| 副作用 | 讀取、草稿、權威變更或對外投遞；哪些需要確認、哪些已有預授權 |
| 範圍 | 資料空間、對象、可見內容、允許動作、收件人／渠道／觸發／fallback 規則及授權版本 |
| 結果能力 | 是否可查原操作、冪等語義、哪些投遞證據可得；沒有送達／已讀回執就保持未知 |
| 有界運行 | Server 設定的模型／工具呼叫及重試限制、已使用次數、總開關和停止原因 |

能力與授權是兩組條件。已綁定渠道、可調用工具、符合家庭角色、對方被選為负责人，均不能互相代替。P2 Web Push／Telegram、P3 FCM 的前置與證據映射由 adapter 實現；Telegram 須先啟動 bot 並核實帳號綁定。

## 調用流程

1. Server 依當前角色、用途及配方過濾工具，提供最小上下文與剩餘額度。
2. 模型回傳自然回答、工具請求或草稿；它不能把自己的 `actionRequests` 批准為可執行。
3. Server 校驗參數、來源、對象、權限／授權版本、終態、資料版本／世代與穩定識別。預授權內可自動執行；範圍外才進必要確認流程。
4. 權威服務協調事務、競態、租約及投遞。工具 SDK 自動執行也必須經同一檢查，不能繞過 Server 的批准層。
5. 把真實結果／證據返回模型，或在不需推理時由程式用清楚文字回報。人機互動必須有收尾，不為生成收尾而再次執行副作用。

正常純聊天不強制第二次模型請求；原生工具循環依需要進行。確定性時間計算、統計、權限與已確認提醒不應為了配合 prompt 被強迫經模型處理。

## 工具結果語義

結果須關聯原請求／操作，含實際狀態、已確認版本或證據、錯誤類別及可否安全核對／重試。模型可見參照不需要含供應商敏感目標。

| 條件 | 模型行為與應用處理 |
|---|---|
| 確認成功 | 只報成功項目；保存確認與資料／任務確認分開 |
| 部分成功 | 列出已確認部分及未完成部分；不重試已成功部分、不宣稱跨工具原子成功 |
| 確定未生效且可重試 | 保留原邏輯識別，在剩餘上限內處理；技術重試不新增任務或重置跟進額度 |
| 結果未知／逾時 | 查原操作／投遞，不能改識別、工具或渠道盲重做；沒有核對能力則保留 unknown，結束本次嘗試並交回待處理 |
| 拒絕／撤權／終態 | 停止受影響動作；不得改用其他渠道規避拒絕 |
| 版本衝突／舊世代 | 重新讀取權威資料並處理衝突；不能套舊確認覆蓋新資料 |
| 模型輸出無效／超限 | 拒絕執行；按有限修正額度處理，耗盡後用清楚狀態收尾，保留當前輸入 |
| 模型服務失敗 | 不把已確認的副作用重做。應用可按工具台帳用確定性文字交代；不能承諾尚未建立的重試或聯絡 |

## 聯絡與恢復的組合規則

`accepted`、送達、閱讀、使用者回應、確認完成是不同證據。已接受但無已讀回執，可以按已授權且實際到期的「未回應」條件有限跟進；不能把理由改成未送達／未讀。未知是否接受時，必須先核對，不進盲目 fallback。

每次執行／fallback 重新核對授權、任務終態、內容版本、成員權限、綁定、額度及原投遞；記錄來源投遞、規則與停止原因。撤權與投遞競態保留實際結果；已被外部服務接受的訊息不保證能撤回。

worker 重啟、租約到期及並發沿用原 `occurrenceId`／工作／投遞識別。舊工具退役也不能把 unknown 改成 failed。新能力須確認語義相容並保留原授權範圍；不自動用近似工具補做。

Server 搬遷／災備先保持任務暫停，檢查單主、世代、授權和 unknown 台帳；模型不能批准恢復。恢復後過期事項集中待處理，不補發整段停機通知。權威定義見 [通知模型](../../docs/DATA_MODEL.md#notification-model) 及 [遷移](../../docs/ARCHITECTURE.md#section-6-4)。
