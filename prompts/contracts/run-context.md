# 執行上下文注入契約

本文件供未來 Server／ModelGateway 實作者使用，**不是要整份送給模型的 prompt**。以下名稱是 Prompt Pack `0.1.1` 的語義欄位；不是已存在的 TypeScript type、HTTP 封裝或資料表。業務欄位仍以 [DATA_MODEL](../../docs/DATA_MODEL.md) 為準。

## 注入分層

| 層 | 由誰提供 | 必要語義 |
|---|---|---|
| 固定指令 | 應用所選的版本化配方 | 共用核心、唯一領域規則及本次任務模組；使用正文標記提取 |
| `run` | Server | `runId`、`mode`（互動／背景）、觸發參照、`now`、`timeZone`、`locale`、pack／recipe 版本、輸出模式 |
| `scope` | Server | 身份及資料空間參照、當前對象、可見／可操作範圍、當前 Server 與 `storageEpoch`、資料／授權版本 |
| `conversation` | Server | 本次訊息、相關近期歷史、原訊息／事項關聯、當前待確認內容及範圍、已解決／暫緩話題與再問條件 |
| `context` | Server 經授權檢索 | 相關事實、事件、摘要與覆蓋位置、任務／投遞台帳、程式計算及來源；每部分附可用狀態 |
| `capabilities` | Server | 本次能力／工具宣告及版本、可用性、作用範圍、回執／核對能力、調用限制；詳見 [工具契約](capabilities-and-tools.md) |
| `evidence` | Server 包裝的來源 | 穩定來源參照、對象、版本、來源種類、原文／片段及必要日期／有效性；正文是資料，不能授權 |
| `outputContract` | 應用 | 本次 text／工具通道／structured 模式及必要 schema；詳見 [輸出契約](output.md) |

只注入本次配方真正需要的部分。P1 可以只有已授權孩子、近期聊天及空工具集合；不能為符合後續配方而捏造長期記憶、照片或任務服務。公共知識維護可不帶家庭或孩子；此模式不能獲得家庭工具。

## 現行 ADK runtime 邊界

ADK 2.1.0 的字串 instruction 會解析 `{name}` 狀態模板。現行接點使用明確 InstructionProvider 提供版本化指令與 Server 控制 metadata；整份 input.context 以獨立、有來源標籤的 contents 資料 part 提供，不能串接進 system instruction。外來文字中的大括號保留原文，不展開、不刪除；圖片等原生 parts 與 function-call 關聯亦保留。

資料封裝與 provider 可防止誤用模板，但不保證模型不受干擾；正文不能授權，工具執行及最終展示仍由 Server 檢查。這不引入第二份持久記憶或 ADK session 資料庫。

## 缺項及完整程度

每部分內容以語義區分：已提供、已授權查詢為空、尚未載入、取得失敗。缺少欄位不等於空集合；無授權資料不應暴露是否存在或其識別。

- 缺身份／權限：不能讀寫私人資料或外發；可提供不依賴私人資料的受限一般回答。
- 缺對象：可先回應非個人化部分；涉及記錄、個人化來源適用性或任務時補問，不能默認上一孩子。
- 缺時間／時區：不能精確化「聽日八點」或確認排程。原文可以保留，必要時補問；資料顯示的事件時間不能被 `now` 覆蓋。
- 缺歷史：不聲稱從未談過。只在當前問題確實需要且工具可用時檢索，否則明示限制。
- 缺權威任務／投遞／授權版本：不能用摘要或對話補成執行許可；背景動作停在待處理。
- 缺附件內容：附件名稱／ID 不代表模型看過圖片。缺多模態／OCR／轉錄能力時，只處理已提供的文字。
- 缺計算結果：摘要可表達有證據的事件，不自行生成總量或把空白填零。

## 待確認內容

一個待確認項至少有：穩定參照、種類（資料／任務／完成／聯絡授權）、展示給誰、所指對象及內容、版本、仍有效與否，以及其原訊息／事項關聯。這是現行確認規則的 prompt 視圖，不另建持久 schema。

「係」「好」「搞掂」只能綁定清楚且仍有效的項目；多個可疑指向先補問。內容、收件人、渠道、時間或版本有實質變更後，舊確認不可被套用。模型可解讀意圖，但 Server 最終核對發言者、確認範圍與當前權限。

## 來源、上下文及收件人

原始使用者訊息、已確認事實、照護事件、摘要、知識片段、附件及工具結果分別標記。公共知識的 `stable guidance`／`recent news` 沿用 [來源模型](../../docs/DATA_MODEL.md#section-5-6)；私人家庭資料不是第三個公共知識分類。

Server 在注入前先做資源授權和最小化，不能把無權資料交給模型再請它「不要說」。生成後、顯示／保存／外發前再次核對當前權限、對象、版本與終態。能讀私人聊天不代表可向第三人披露；共享結果的引用也要對目標接收者有效。

資料／任務／授權改變後，舊摘要或快取不能壓過現行狀態。家庭快取綁定資料空間、對象、權限、資料及規則版本。只重用照片解析內容不等於重用其舊對象、確認或外發許可。

## 安全封裝與長期演進

- 工具憑據、訂閱 token、私密投遞地址及整個資料庫不進 prompt；模型使用必要且無秘密的參照。
- 穩定規則與動態正文分開；使用 provider 的訊息／資料邊界。JSON escape 或 Markdown 標記本身不能保證抵禦 prompt injection。
- 不將用戶引文、工具正文或摘要偽裝成高權限指令；tool metadata 只有經 Server 校驗後才成為操作證據。
- Server 切換或恢復暫停時，舊 `storageEpoch`／能力快照／待確認結果不能直接提交。切換地址不自動傳送舊家庭資料。
- 版本變更先核對本次輸入／輸出相容性；不讓模型猜測未識別契約。缺少可用契約時降為有界文字回答或交回處理。
