# Prompt Pack 靜態審查

本目錄檢查文件是否完整、一致、可追溯。合成輸入和預期輸出由作者指定，**沒有呼叫模型，不能證明 Gemini 實際會遵循**。本目錄只記錄靜態驗證方法；產品已有部分正式入口，實際接線見 [配方對照](../recipes/README.md#runtime-entry-map)，各項真實验收狀態見根 PLAN 與對應 EV，不能用本目錄的例子代替。

## 材料

- [多輪對話](conversations.md)：人機對話、工具結果與收尾的合成例子。
- [場景矩陣](cases.json)：52 個合成場景，記錄觸發條件、預期／禁止行為及權威 REQ／AC。
- [P1 最小入口](../p1/README.md)：可獨立採用的文字 prompt，另附 9 個靜態情景；不依賴完整包。
- [契約範例](../contracts/examples.json)：12 個可解析的輸入／輸出 fixture，全部標記 synthetic。
- [需求映射](traceability.md)：現行產品條款與模組、案例、後續驗收工作包。
- [靜態檢查](check.ps1)：只讀本包及必要權威文件，輸出 JSON 報告；不呼叫模型、網絡、產品服務或更改檔案。

## 可重跑命令

在倉庫根目錄的 PowerShell 7.2 或更新版本執行：

```powershell
& ./prompts/review/check.ps1
```

整包版本、各模組版本及合成案例格式版本各自維護；只要求語法有效、模組檔頭與 manifest 該項一致，不能要求它們全部等於整包版本。沒有 PowerShell 時，可跑 `node --test tests/agent-prompt.test.ts` 及本包新增定向檢查；不把 Node 局部通過聲稱為 PowerShell 全腳本已通過。

檢查範圍：manifest／JSON 解析、ID 唯一、版本、模組路徑／正文標記／依賴、manifest 全部十二個配方的閉包、必要對話核心與領域安全、來源錨點／本地連結、範例共同欄位、語義 fixture 的明確標記與七類場景覆蓋。檢查只對文件和人工指定的 expected 資料斷言，不把文字 keyword 比對當模型行為測試。

人工靜態閱讀另外檢查：

1. 每個模組正文真正直接向 Agent 下達可遵循的指令，不只寫功能需求。
2. 共用安全限制與領域／任務規則無放寬衝突；只在本次任務需要時補問。
3. 說給人的文字與程式候選／操作狀態一致，成功須有證據。
4. 對正常、缺資料、衝突、工具失敗、權限不足、結果不確定及需確認七類情況有明確處理；無工具／背景／跨模組時也適用。
5. 已授權自動聯絡不被每次確認卡住；unknown 不盲重發；私隱、撤權和終態不能由新渠道、快取或舊摘要繞過。
