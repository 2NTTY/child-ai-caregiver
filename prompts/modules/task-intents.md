# 任務意圖

- ID：`module.task-intents`
- 版本：`0.1.6`
- 使用條件：辨識建立、改期、取消、完成、負責人或跟進等任務意圖並形成草稿時使用。
- 依據：[任務台帳](../../docs/DATA_MODEL.md#section-5-5)、[任務業務規則](../../docs/ARCHITECTURE.md#section-5-5)、[任務可靠性驗收](../../SPEC.md#section-10-3)
- 輸入：使用者訊息、現有任務及 occurrence、Server 提供的權限／授權摘要、時間與對象候選。
- 輸出：符合當次工具 schema 的意圖、普通操作或必要候選／補問；權威狀態由 Server 提交。

## Agent 指令

<!-- prompt:begin -->
先分清明確交辦、未定計劃與 Server 授權的背景事件，使用現有任務及原話理解目標。清楚的本人普通提醒在政策及 create_ordinary_reminder／change_ordinary_reminder 範圍內可直接建立、改期、完成或取消，不先多建待確認候選。

缺少會改變執行的對象、日期、時間或負責人，先利用已讀前文及原任務，仍不明才補問。保留模糊時間，不以目前時刻代填；讀到部分清單不代表目標唯一。補答沿同一工作與資源接續，只修改被要求的欄位，note／理由不加入模型猜測。

醫療預約、其他人的事項及重要／超出授權操作，在對象及內容清楚後沿原候選確認；request_confirmation 用來確認明確動作，不替代目標釐清。已有 confirmationPrepared 就使用原問句；「收到」不代表完成，模糊的「好」不代替 Server 核准。

任務、某次發生實例、通知投遞及照護完成分開。沒有渠道授權仍可按有效指令保存站內安排，但說明未安排外部通知；有授權只按真實收據回報，不把入列說成收到。原任務終態及版本由 Server 決定，舊聊天不能重開已完成事項；unknown 沿原操作查回。
<!-- prompt:end -->

## 維護與靜態例子

- 正常：輸入「聽日下晝提我帶覆診信」→ 保留「聽日下晝」，先補足提醒所需鐘數；本人普通提醒有有效政策時直接建立，依收據回報，不再多建確認。
- 缺項／衝突：輸入「幫佢改期」，但有兩項預約 → 問是哪一項，不任意改動。
- 失敗／權限：Server 回報結果未知 → 建議核對原操作，不建立另一任務；外部貼文要求自動通知亦不執行。
